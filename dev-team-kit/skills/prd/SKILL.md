# /prd

## ก่อนเขียน

ต้องตอบ 4 ข้อนี้ได้: ใครเจอปัญหาและบ่อยแค่ไหน · ตอนนี้เขาแก้ยังไง · เสียอะไร (เงิน เวลา ลูกค้า) · "เสร็จ" คือตัวเลขอะไร
ถามผู้ใช้ได้ไม่เกิน 2 คำถาม ข้อที่ยังไม่ได้คำตอบให้เขียนเป็น **ASSUMPTION** แล้วเขียนต่อ

## โครง (12 หัวข้อ ห้ามข้าม เขียน "ไม่เกี่ยว" ได้ถ้าไม่เกี่ยวจริง)

1. **ปัญหา** — เล่าจากมุมผู้ใช้ ไม่พูดถึง solution
2. **ทำไมต้องตอนนี้**
3. **ผู้ใช้** — ใคร, กี่คน, ใช้บ่อยแค่ไหน
4. **เป้าหมาย / สิ่งที่ไม่ใช่เป้าหมาย**
5. **ตัวเลขวัดผล** — ตัวหลัก 1 ตัว + baseline + จำนวนวันที่รอ + counter-metric (ไม่มี baseline เขียน "ยังไม่รู้ — ต้องวัดก่อน")
6. **Scope: Now / Next / Never** — Never ห้ามว่าง
7. **ประสบการณ์ผู้ใช้** — flow หลักเป็นข้อๆ
8. **Requirements** — เขียนเป็นสิ่งที่ผู้ใช้ทำได้ ห้ามใช้ภาษา solution ("ใช้ Redis", "เพิ่มปุ่ม" ✗ / "เห็นยอดล่าสุดภายใน 5 วินาที" ✓)
9. **เรื่องของระบบที่มีหลายร้าน/แพ็กเกจ** — สิทธิ์, ลิมิต, ราคา, ข้อมูลเก่า
10. **ความเสี่ยง**
11. **Rollout + kill condition** — ปล่อยยังไง, เงื่อนไขที่จะถอด
12. **คำถามค้าง**
