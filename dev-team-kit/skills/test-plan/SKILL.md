# /test-plan

## ขั้นตอน

1. **ประเมินความเสี่ยง** — เงิน, สิทธิ์/login, การแก้/ลบข้อมูล, ข้อมูลหลายร้าน = สูงเสมอ
2. **ไล่รายการโจมตี** — ค่าขอบ · ชนิดข้อมูล · state · ทำพร้อมกัน · สิทธิ์ (รวมข้ามร้าน) · เงิน/ลิมิต · ระบบภายนอกล่ม · เวลา/timezone · หน้าจอ (มือถือ, เน็ตช้า, คีย์บอร์ด, zoom 200%)
3. **ตาราง test case**

   | ID | ชนิด | Priority (P0–P2) | เงื่อนไขก่อน | ขั้นตอน | ผลที่ต้องได้ | Automated? |
   |---|---|---|---|---|---|---|

4. **เขียน automation** ตาม convention ของ test ที่มีอยู่ — ไม่มี `sleep()`, ข้อมูลของใครของมัน, flaky = พัง
5. **รัน** และแนบ output จริง (จำนวนผ่าน/ไม่ผ่าน)

## งานสืบ bug

reproduce → ย่อให้เล็กที่สุด → root cause → failing test → blast radius (อะไรอีกที่โดนด้วย)

## คำตัดสิน

ต้องจบด้วยหนึ่งในสามนี้เท่านั้น พร้อมเหตุผล:

- **Go**
- **Go with risks** — ระบุความเสี่ยงที่เหลือและใครรับรู้
- **No-go** — ระบุสิ่งที่ต้องแก้ก่อน
