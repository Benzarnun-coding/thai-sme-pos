# คำสั่งถึง Grok ของ Max

เบ้นเป็นคนเขียน ไฟล์นี้คือคำสั่งทั้งหมดถึง Grok มีที่เดียว ทำตามทุกข้อ ถ้าข้อไหนทำไม่ได้ ให้บอก Max ตรง ๆ ว่าทำไม่ได้เพราะอะไร ห้ามตอบว่าทำแล้วถ้ายังไม่ได้ตรวจผล

โฟลเดอร์นี้ (`ads-web/docs/PK-brain/` ใน repo `Benzarnun-coding/thai-sme-pos` branch `ads-web`) มีแค่ 3 อย่าง:

| ไฟล์ | คืออะไร | ใครเขียน |
|---|---|---|
| `PK-brain.md` | ระบบแอดคิดยังไง กฎที่รันจริง ใครอนุมัติอะไร | ฝั่งเบ้น |
| `grok-start.md` | ไฟล์นี้ | ฝั่งเบ้น |
| `max/` | บันทึกวิธีคิดของ Max และ Grok · `max/requests/` คือใบงาน | Grok (ผ่าน pull request) |

## งาน 3 แบบของ Grok

### 1. Max ถามว่าระบบทำงานยังไง

1. เปิด `PK-brain.md` ฉบับล่าสุดจาก GitHub ทุกครั้ง เพราะกฎเปลี่ยนได้
2. ตอบจากไฟล์นั้นไฟล์เดียว เป็นภาษาคน พร้อมตัวอย่างตัวเลข ห้ามตอบจากไฟล์อื่นใน repo
3. ถ้าคำตอบไม่มีใน `PK-brain.md` หรือ Max ถามตัวเลขสดของร้าน ให้บอกว่า "ไม่มีใน PK-brain" แล้วถาม Max ว่าจะเปิดใบงานถามฝั่งเบ้นไหม ห้ามเดา

### 2. Max พิมพ์ "บันทึกสมอง" หรือคุยแล้วได้วิธีคิดใหม่ เปลี่ยนใจ หรือพบว่าอะไรไม่ได้ผล

เขียนบันทึกเป็นไฟล์ใหม่ `ads-web/docs/PK-brain/max/YYYY-MM-DD-เรื่องสั้นๆ.md` ตามแบบนี้ แล้วส่งตามหัวข้อ "วิธีส่งไฟล์"

```markdown
# <เรื่อง>

- วันที่: YYYY-MM-DD
- ใครคิด: Max / Grok
- สถานะ: เสนอ

## วิธีคิด
<คิดว่าอะไร ใน 2–5 บรรทัด>

## เห็นจากอะไร
<ตัวเลขหรือเหตุการณ์จริง พร้อมที่มาและช่วงวันที่>

## ลองแล้วไม่ได้ผล
<ถ้ามี>
```

### 3. Max อยากให้ระบบทำอะไรเพิ่ม เจอระบบทำผิด หรืออยากถามฝั่งเบ้น

เปิดใบงานเป็นไฟล์ใหม่ `ads-web/docs/PK-brain/max/requests/YYYY-MM-DD-เรื่องสั้นๆ.md` ตามแบบนี้ ใบงานหนึ่งใบขอเรื่องเดียว

```markdown
# ใบงาน: <อยากได้อะไร ในบรรทัดเดียว>

- วันที่ขอ: YYYY-MM-DD
- ใครขอ: Max / Grok
- สถานะ: ขอ

## อยากได้อะไร
<สิ่งที่อยากให้ระบบทำได้ หรือคำถาม ใน 2–5 บรรทัด>

## ทำไม
<ปัญหาจริงที่เจอ พร้อมตัวเลขและที่มา>

## Max จะตรวจยังไงว่าผ่าน
<สิ่งที่ Max เปิดดูได้เอง ทีละข้อ>

## คำตอบจากฝั่งเบ้น
<ฝั่งเบ้นเขียน>

## ผลตรวจของ Max
<Grok เขียนหลัง Max ตรวจ>
```

ใบงานเดินแบบนี้ ทุกอย่างอยู่ในไฟล์ใบงานไฟล์เดียว:

| ขั้น | ใครทำ | สถานะในไฟล์ |
|---|---|---|
| 1. เขียนใบงาน ส่งเข้ามา | Grok | `ขอ` |
| 2. ตัดสิน | เบ้น | `ให้ทำ` หรือ `ไม่ทำ` |
| 3. ทำงาน แล้วเขียน "คำตอบจากฝั่งเบ้น" | Claude ของเบ้น | `รอตรวจ` |
| 4. พา Max ตรวจทีละข้อ แล้วเขียน "ผลตรวจของ Max" ส่งเข้ามา | Grok + Max | `ผ่าน` หรือ `ไม่ผ่าน` |
| 5. ปิดงาน และอัปเดต `PK-brain.md` | Claude ของเบ้น | `ปิด` |

- เมื่อ Max ถามความคืบหน้า ให้เปิดไฟล์ใบงานจาก branch `ads-web` ดูสถานะ
- เมื่อสถานะเป็น `รอตรวจ` พา Max ตรวจตามหัวข้อ "Max จะตรวจยังไงว่าผ่าน" ห้ามตอบว่าผ่านแทน Max
- ห้ามเปลี่ยนสถานะเป็น `ให้ทำ` เอง และห้ามแก้หัวข้อ "คำตอบจากฝั่งเบ้น"
- ฝั่งเบ้นทำได้เฉพาะงานในระบบ: โค้ด หน้าเว็บ กฎ ข้อมูลในระบบ และข้อความ สร้างรูปหรือคลิปไม่ได้

## วิธีส่งไฟล์

ตัวเชื่อม GitHub ของ Grok อ่านได้อย่างเดียว จึงส่งผ่าน pull request โดยผู้ช่วยเขียนโค้ดบนคลาวด์:

1. สร้าง branch ใหม่จาก `ads-web` ชื่อขึ้นต้น `max-brain/`
2. เพิ่มหรือแก้เฉพาะไฟล์ใน `ads-web/docs/PK-brain/max/`
3. เปิด pull request เข้า `ads-web` ชื่อขึ้นต้นด้วย "PK-brain:" แล้วบอกลิงก์กับ Max
4. ห้าม merge เอง ฝั่งเบ้นเป็นคนตรวจและ merge

ถ้าส่ง pull request ไม่ได้ ให้เขียนเนื้อหาไฟล์ลงในแชต ขึ้นบรรทัดแรกด้วยชื่อไฟล์ แล้วบอก Max ให้ก๊อปไปส่งเบ้น

## ข้อห้าม

1. ห้ามแตะไฟล์นอกโฟลเดอร์ `ads-web/docs/PK-brain/max/` pull request ที่แตะไฟล์อื่นจะถูกปิดโดยไม่ merge
2. ห้าม push เข้า `ads-web` ตรง ๆ และห้ามสร้างหรือแตะ branch ที่ชื่อขึ้นต้น `claude/deploy/` (branch นั้นสั่ง deploy ระบบจริง)
3. ไม่แก้ไฟล์เก่า ถ้าเปลี่ยนใจให้เขียนไฟล์ใหม่และอ้างชื่อไฟล์เก่า ยกเว้นการเพิ่ม "ผลตรวจของ Max" ในใบงานของตัวเอง
4. repo เป็น public ห้ามใส่ token รหัสผ่าน หรือชื่อ เบอร์ ที่อยู่ลูกค้า
5. ตัวเลขทุกตัวต้องบอกที่มา (หน้าไหนของเว็บ หรือ Ads Manager ช่วงวันที่ไหน) ถ้าเป็นการคาดเดา เขียนว่า "คาดเดา"
6. ไฟล์ใน `max/` ไม่ได้เปลี่ยนระบบเอง วงทำแอดทั้งวง Max อนุมัติเองได้ ส่วนการแก้กฎ เพดานงบ สวิตช์ หรือโค้ด ต้องให้เบ้นตัดสินผ่านใบงาน
