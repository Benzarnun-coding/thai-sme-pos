# ใบงาน: ส่งเคสจากช่อง Discord ปัญหา-ai-สรุปบิล ไปที่ webhook ของอูนิด้วย

- วันที่ขอ: 2026-11-18 (18 พ.ย. 2569)
- ใครขอ: Max / Grok
- ผู้ทำ: เบน
- สถานะ: ให้ทำ (เบ้นให้ทำ 2026-11-19 · ฝั่งเบ้นสร้างเสร็จ 2026-11-19 แบบปิดสวิตช์ ยังไม่ได้ขึ้นระบบจริง ยังตรวจไม่ได้)

## อยากได้อะไร
1. ทุกครั้งที่ระบบโพสต์เคสลงช่องนี้ ให้ส่ง HTTP POST แบบ JSON ไปที่ webhook URL ของอูนิด้วย (โพสต์ Discord ตามเดิมเหมือนเดิม)
2. JSON ควรมีอย่างน้อย: `bill_no` (เช่น 33605), `customer_name`, `admin_summary` (บรรทัด "แอดมินสรุป"), `status_header` (เช่น "ใส่บิลให้แล้ว แต่ช่วยเช็กก่อนส่งบิล" หรือ "บิลนี้ต้องให้คนดู"), `issues` (รายการ bullet ปัญหา), `posted_at`, และลิงก์ข้อความ Discord ถ้ามี
3. webhook URL และ sender key Max จะส่งให้เบนทางแชตส่วนตัว ห้ามใส่ใน repo นี้ (repo เป็น public) ให้เก็บเป็น secret/env ในระบบ
4. ส่งแบบเคสละ 1 request หรือรวมหลายเคสใน request เดียวก็ได้

## ทำไม
ตอนนี้บอท "น้องอูนิ" ในระบบของเบนโพสต์เคสบิลที่ต้องเช็กลงช่อง Discord "👽-ปัญหา-ai-สรุปบิล" (เซิร์ฟเวอร์ PK Team) และแท็กแอดมิน Max อยากให้เคสพวกนี้ถูกส่งไปให้ อูนิ (Grok Bot) ด้วย เพื่อให้อูนิหาคนแก้แล้วส่งให้บอท 365 PAGE แก้บิลและตอบลูกค้า โดยทำงานเฉพาะตอนมีเคสจริง ไม่ต้องเปิดดู Discord ทุก 30 นาที (ประหยัดโควตา)

## Max จะตรวจยังไงว่าผ่าน
เช็กลิสต์ให้ Max ตรวจ หลังเบนทำเสร็จ:

- [ ] เคสใหม่ในช่อง Discord ไปถึงอูนิภายในไม่กี่นาที
- [ ] ข้อมูลที่ส่งมามีเลขบิล ชื่อลูกค้า แอดมินสรุป และปัญหาครบ
- [ ] ไม่มี URL หรือ key อยู่ใน repo
- [ ] พอผ่านแล้ว อูนิจะปิดรอบเช็ก Discord ทุก 30 นาที

## คำตอบจากฝั่งเบ้น

เขียนโดย Claude ของเบ้น 2026-11-19

**ทำแล้ว (อยู่ในโค้ด branch `ads-web` ยังไม่ได้ขึ้นระบบจริง และสวิตช์ปิดอยู่)**

- ทุกเคสบิลที่น้องอูนิโพสต์ลงช่องปัญหาบิล ระบบส่ง HTTP POST แบบ JSON ไป webhook ของอูนิด้วย เคสละ 1 request โพสต์ Discord เหมือนเดิมและไม่รอ webhook
- key ส่งใน header ชื่อ `Authorization` ค่าตรงกับช่อง "ส่วนหัว Authorization" ในแผงตั้งค่า webhook ทุกตัวอักษร (แก้ 2026-11-19 ตามคำตอบของอูนิ เดิมใช้ `X-Sender-Key`) · รอคำตอบไม่เกิน 5 วินาที ไม่ส่งซ้ำ ถ้า webhook ล่ม เคสยังอยู่ใน Discord ตามปกติ
- รับเฉพาะ URL ที่ขึ้นต้น `https://`
- URL และ key เก็บเป็น secret ของระบบ ไม่อยู่ใน repo

**หน้าตา JSON ที่จะส่ง (ตัวอย่าง ไม่ใช่ลูกค้าจริง)**

```json
{
  "bill_no": 33605,
  "customer_name": "ตัวอย่าง (ไม่ใช่ลูกค้าจริง)",
  "admin_summary": "501/1 31 cod 249",
  "status_header": "บิลนี้ต้องให้คนดู",
  "issues": ["501/1 ไม่มีไซส์ 31 — รุ่นนี้มี 28, 29, 30, 32, 34, 36 · ต้องถามลูกค้าใหม่"],
  "posted_at": "2026-11-19T03:00:00.000Z",
  "discord_message_url": null
}
```

- `status_header` มี 2 ค่า: "ใส่บิลให้แล้ว แต่ช่วยเช็กก่อนส่งบิล" หรือ "บิลนี้ต้องให้คนดู"
- `bill_no` เป็น `null` ได้ เมื่อยังไม่มีร่างบิล · `customer_name` เป็นชื่อ Facebook ถ้าไม่รู้ชื่อจะเป็น "ไม่ทราบชื่อ"
- `posted_at` เป็นเวลา UTC · `issues` มีไม่เกิน 6 ข้อ

**ที่ไม่ได้ทำตามที่ขอ**

- `discord_message_url` เป็น `null` เสมอ เพราะช่องทางที่ระบบใช้โพสต์ไม่คืนลิงก์ข้อความกลับมา
- ส่งเฉพาะเคสบิล ไม่ส่งข้อความอีก 3 แบบในช่องเดียวกัน: แจ้งเตือนทั้งร้าน (ล็อกอิน Page365 หลุด, แชทไม่เข้า), "ข้อความเหมือนสรุปแต่อ่านไม่ออก", และ "ส่งยอดขายให้ Meta ไม่สำเร็จ" ถ้าอยากได้ด้วยให้เปิดใบงานเพิ่ม

**ที่ต้องเกิดก่อน Max ตรวจได้**

1. Max ส่ง webhook URL และค่าช่อง "ส่วนหัว Authorization" ให้เบ้นทางแชตส่วนตัว
2. เบ้นใส่ secret 2 ตัว และสั่งขึ้นระบบจริง
3. เบ้นเปิดสวิตช์ "ส่งเคสบิลให้อูนิ" ในหน้า Log ออเดอร์แชท
4. ฝั่งเบ้นเปลี่ยนสถานะใบงานเป็น `รอตรวจ` แล้ว Max ตรวจตามเช็กลิสต์ด้านบน

**ที่ตรวจแล้ว / ยังไม่ได้ตรวจ**

- ตรวจแล้วด้วยชุดทดสอบของโค้ด: ปิดสวิตช์ไม่มีอะไรออก, เปิดแต่ไม่มี secret ไม่มีอะไรออก, เปิดพร้อม secret ส่ง 1 ครั้งพร้อม key ใน header, webhook ล่มหรือปฏิเสธไม่ทำให้ระบบบิลสะดุด
- ยังไม่ได้ตรวจ: การส่งถึง webhook จริงของอูนิ เพราะยังไม่มี URL และยังไม่ได้เปิด
