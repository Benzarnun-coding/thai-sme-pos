# ads-web

เว็บคุม Meta Ads ของ PkJeans รันบน Cloudflare (แพ็กเกจฟรี)

- **4 กลุ่มตามช่วงชีวิตแอด** (ทดลอง → ทดสอบระบบ → ทำเงิน → ดับ/ทดสอบใหม่) คุณจัดแคมเปญเข้ากลุ่มเอง แคมเปญที่ยังไม่จัด ระบบไม่แตะ
- เริ่มต้น **ทุกกลุ่มไม่มีกฎ** และทุกแคมเปญอยู่ "ยังไม่จัด" = ดูข้อมูลอย่างเดียว ไม่มีอะไรเปลี่ยนบน Meta จนกว่าจะตั้งกฎเอง (มีปุ่ม "ใส่กฎแนะนำ" ในแต่ละกลุ่ม)
- **กฎอยู่ที่กลุ่ม** แต่ละกลุ่มมีชุดกฎของตัวเอง (หยุด / ปรับงบ / แจ้งเตือน / **ย้ายกลุ่มอัตโนมัติ**) และแคมเปญไหนจะใช้กฎเฉพาะของตัวเอง หรือปิดอัตโนมัติก็ได้
- กฎย้ายกลุ่มมีเงื่อนไข "ยอดซื้อ ≥ N" และ "อยู่ในกลุ่มนี้ ≥ N วัน" กันไม่ให้ย้ายเพราะฟลุคหรือเด้งไปมา การย้ายไม่แตะ Meta แค่เปลี่ยนกลุ่ม แล้วรอบถัดไปจะใช้กฎของกลุ่มใหม่
- **สินค้า/ต้นทุน** แยกอีกแกน: แคมเปญจับคู่สินค้าจากคำในชื่อ สินค้าผูกต้นทุนจาก Google Sheet (Master Catalog คอลัมน์ H) → ได้ **ROAS คุ้มทุน** ต่อสินค้า กฎที่ตั้งเป็น "× จุดคุ้มทุน" จึงใช้ชุดเดียวกับทุกสินค้าได้ เพราะเกณฑ์ปรับตามต้นทุนของแต่ละตัวเอง
- ระบบรันกฎเองวันละ 2 รอบ (08:00, 20:00) ปุ่มเปิด/หยุด/ปรับงบด้วยมืออยู่ในหน้าเดียวกัน
- ไม่ใช้ AI ในลูปประจำวัน คุยกับ Meta ด้วย System User token ของร้านเอง

```
Google Sheet ──(07:30 ทุกวัน)──▶ D1: costs
Meta API ◀──(08:00, 20:00)── Worker: แยกตามกลุ่ม × สินค้า → คิดจุดคุ้มทุน → เช็คกฎ (ads-engine) → ปรับตาม guardrails → ย้ายกลุ่ม → log → LINE
หน้าเว็บ ◀── Cloudflare Access (ล็อกอินด้วยอีเมล) ──▶ Worker API
```

ใช้ลอจิกกฎ, guardrails และตัวคุยกับ Meta ชุดเดียวกับ `../ads-engine` (import ตรง ไม่ได้ copy)

## ขึ้นเซิร์ฟเวอร์ครั้งแรก

ทำครั้งเดียว ใช้เวลาราว 20 นาที ทุกขั้นฟรี

1. สมัคร Cloudflare ที่ dash.cloudflare.com (ไม่ต้องมีโดเมน)
2. ล็อกอิน wrangler

```bash
cd ads-web && npx wrangler login
```

3. สร้างฐานข้อมูล แล้วเอา `database_id` ที่ได้ไปแทน `00000000-…` ใน `wrangler.jsonc`

```bash
npx wrangler d1 create pkjeans-ads
```

4. ใส่ Meta token (System User, สิทธิ์ `ads_read` + `ads_management` — วิธีสร้างดู `../ads-engine/README.md`)

```bash
npx wrangler secret put META_ACCESS_TOKEN
```

5. (ไม่บังคับ) รายงานเข้า LINE

```bash
npx wrangler secret put LINE_CHANNEL_ACCESS_TOKEN
```

```bash
npx wrangler secret put LINE_TO
```

6. ขึ้นเว็บ จะได้ลิงก์ `https://pkjeans-ads.<ชื่อบัญชี>.workers.dev`

```bash
npm run deploy
```

7. **ล็อกเว็บด้วย Cloudflare Access** — ก่อนทำขั้นนี้ API จะปฏิเสธทุกคำขอ (ตั้งใจให้ปิดไว้ก่อน)
   - Cloudflare dashboard → Workers & Pages → pkjeans-ads → Settings → Domains & Routes → แถว `workers.dev` → เปิด **Cloudflare Access**
   - ตั้ง policy ให้เฉพาะอีเมลของคุณและทีมเข้าได้
   - คัดลอก **Application Audience (AUD) tag** และ **team domain** (`https://<ทีม>.cloudflareaccess.com`) มาใส่ `ACCESS_AUD` และ `ACCESS_TEAM_DOMAIN` ใน `wrangler.jsonc` แล้ว `npm run deploy` อีกรอบ
8. เปิดเว็บ → ตั้งค่า → ใส่ **Google Sheet ID** (ไม่เก็บใน git เพราะ repo เป็นสาธารณะ) → **ดึงต้นทุนจากชีตตอนนี้** → แท็บสินค้า/ต้นทุน เพิ่มสินค้าและผูกต้นทุน → หน้าภาพรวม จัดแคมเปญเข้า 4 กลุ่ม → แท็บ **กฎ** ปรับกฎของแต่ละกลุ่ม และตั้งกฎเฉพาะรายแอดถ้าต้องการ
9. ปล่อย **โหมดทดลอง** ไว้สัก 2–3 วัน ดูในหน้าประวัติว่ากฎจะทำอะไร ถ้าโอเคค่อยเปิด "ทำจริง" ในหน้าตั้งค่า

ถ้าแก้โค้ดแล้วอยากขึ้นใหม่ ใช้ `npm run deploy` คำสั่งเดียว (build + migrate + deploy)

## ความปลอดภัย

- Meta token อยู่ใน Cloudflare secret เท่านั้น ไม่เคยส่งไปหน้าเว็บ
- ทุก `/api` ตรวจ JWT ของ Cloudflare Access เอง ถ้ายังไม่ตั้ง Access → ปฏิเสธหมด
- guardrails (หน้าตั้งค่า): กฎอัตโนมัติถูกคุมทุกข้อ (ปรับได้ไม่เกิน X% ต่อรอบ, งบต่อแคมเปญต่ำสุด/สูงสุด, งบรวมทั้งบัญชี) ส่วนการปรับงบด้วยมือเช็คแค่งบต่ำสุด/สูงสุดต่อแคมเปญ
- รอบหนึ่งเปลี่ยนได้ไม่เกิน 25 รายการ ที่เหลือรอรอบถัดไป
- **หยุดฉุกเฉิน** ในหน้าตั้งค่า = หยุดกฎอัตโนมัติทันที
- ทุกการกดเปลี่ยนบันทึกไว้ในหน้าประวัติ ("ใครแก้อะไร")
- ชีตต้นทุนอ่านผ่านลิงก์แชร์ "ทุกคนที่มีลิงก์ดูได้" — ใครได้ลิงก์ก็เห็นต้นทุน ถ้าจะปิดแชร์ต้องเปลี่ยนไปใช้ Google service account (ยังไม่ได้ทำ)

## แพ็กเกจฟรีของ Cloudflare

ออกแบบให้อยู่ในโควตาฟรี: CPU 10ms/ครั้ง, เรียกออกนอก 50 ครั้ง/รอบ, D1 query จำกัดต่อครั้ง
- ต้นทุน: ให้ Google เฉลี่ยต่อรหัสก่อนส่ง (`COST_QUERY` ใน `worker/model.ts`) แท็บ BB จาก 2.6MB เหลือ 88KB
- Google ตอบช้า 5–15 วินาที/แท็บ บนชีตนี้ ปุ่มในหน้าเว็บจึงดึงทีละแท็บ ส่วนรอบอัตโนมัติดึงพร้อมกัน 6 แท็บ
- เขียน D1 แบบก้อนเดียวผ่าน `json_each`

## พัฒนาบนเครื่อง


```bash
npm run dev
```

## โครงสร้าง

| ไฟล์ | หน้าที่ |
|---|---|
| `worker/model.ts` | จับคู่สินค้า, คิดจุดคุ้มทุน/กำไร, แปลงกฎ "× จุดคุ้มทุน" และแยกกฎย้ายกลุ่ม, อ่าน CSV ชีต (ไม่มี I/O มีเทสต์) |
| `worker/engine.ts` | แบ่งตามกลุ่ม × สินค้า แล้วเรียก `evaluate()` ของ ads-engine ทีละก้อน + คำนวณการย้ายกลุ่ม |
| `worker/run.ts` | หนึ่งรอบอัตโนมัติ: ดึง → เช็ค → `applyDecisions()` → log → LINE |
| `worker/index.ts` | API + cron |
| `worker/auth.ts` | ตรวจ JWT ของ Cloudflare Access |
| `worker/costs.ts` | ดึงต้นทุนจาก Google Sheet |
| `worker/mock.ts` | ข้อมูลตัวอย่าง (แคมเปญจริง 21–27 ก.ย.) สำหรับ dev |
| `web/src/` | หน้าเว็บ React |
| `migrations/` | ตาราง D1 + 4 กลุ่ม (เริ่มแบบไม่มีกฎ) |
| `web/src/stageTemplates.ts` | กฎแนะนำของแต่ละกลุ่ม ใช้ผ่านปุ่ม "ใส่กฎแนะนำ" |
